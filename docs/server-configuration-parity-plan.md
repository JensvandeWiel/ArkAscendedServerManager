## 0. Decisions and current status

### 0.1 Decisions

- **ASA only.** An option with `inASA=No` is not implemented. `inASA=Unknown` is allowed only
  with `@Unsure` and (from phase 2) an experimental visual marker. Audit result: **0
  contradictions** among the modelled options.
- **Three sources of truth.** The wiki CSV, the legacy C# manager
  (`C:\Users\jens\MyProjects\ServerManagers`) and the current app. The legacy manager is ASE-era
  and may contradict the wiki; `tools/audit-options.py` reports those differences instead of
  silently resolving them. The current app follows the wiki when they disagree, unless the
  wiki is clearly wrong (see Â§2.1).
- **Mods are stored in both places.** Mods are stored in
  `GameUserSettings.ini > [ServerSettings] > ActiveMods` as comma-separated CurseForge project
  IDs, and the launch line always mirrors that list as `-mods=`. There is no toggle.
  Online research (Oct 2026) found that **both routes work**: `ActiveMods` is the list the engine
  reads; `-mods=` is the documented ASA route and is commonly used because it also downloads and
  updates CurseForge mods on start. If both are present, the launch argument wins, so the lists
  must be identical (the app generates `-mods=` from `ActiveMods`).
- **Units are stored as ARK stores them.** `TribeNameChangeCooldown` is stored raw (default
  `15`); its unit is documented as ambiguous. `TribeSlotReuseCooldown` is seconds in ARK and
  displayed as minutes; only the hint was wrong, not the conversion.
- **No guessing.** When the wiki is contradictory, store the raw value, say so in the hint, and
  verify on a real server. "Implemented" does not mean "verified in game".

## 1. Where the app stands today

Three configuration surfaces are modelled:

| Surface | Model | Serialized to |
|---|---|---|
| Launch command | `Settings.Administration` + `Settings.Options` (`core/.../server/Settings.kt`) | `ShooterGame/Binaries/Win64/startup.bat` |
| `GameUserSettings.ini` | `GameUserSettings` â†’ `SessionSettings`, `MessageOfTheDay`, `ServerSettings` (`core/.../ini/GameUserSettings.kt`) | `ShooterGame/Saved/Config/WindowsServer/GameUserSettings.ini` |
| `Game.ini` | `Game` â†’ `ShooterGameMode` (`core/.../ini/Game.kt`) | `ShooterGame/Saved/Config/WindowsServer/Game.ini` |

UI is organised as tabs in `ui/src/main/kotlin/features/server/ServerScreen.kt`
(Info, Profile, General, Management, Environment, Rules, Player, Dino Settings, Config Editor).

The important thing for this plan: the architecture scales. Adding a property is
model + validation + one Compose field + two strings + CSV flag. There is no schema migration
for the database, because the models are stored as JSON blobs in `servers.settings`,
`servers.game_user_settings` and `servers.game` (Exposed `json<>` columns, `Json { encodeDefaults = true; ignoreUnknownKeys = true }`).
New fields with defaults therefore deserialize fine for existing rows. Unknown INI keys are
already preserved through `WithIgnored`/`ignoredKeys`, so adding modelled options cannot destroy
hand-written custom config.

`ArkServerOptions.csv` `implemented` column is stale: it marks 23 rows, while the UI already
surfaces roughly 108 of the 109 modelled INI properties. This plan treats the CSV as the source
of truth for *what exists*, not for *what is done*.

### 2.1 Data pipeline: scrape the wiki instead of hand-editing

`tools/scrape-ark-options.py`:

- fetches `https://ark.wiki.gg/wiki/Server_configuration?action=raw` (or `--input file.raw`);
- parses the `{{Server config variable}}` templates brace-aware, so nested templates
  (`{{ItemLink|...}}`), multi-line values and inline template closes are handled;
- maps wiki headings to the CSV `Location` convention (Game.ini grouping headings are collapsed;
  only bracketed subsections such as `[ServerSettings]`/`[ModInstaller]` are kept);
- normalises known wiki typos (`inASA = Tes` â†’ `Yes`) and reports them as warnings;
- preserves the `implemented` column (by `Location+name`, then by unique `name`), so a scrape never
  resets progress;
- `--check` prints added/removed/changed rows and exits non-zero, for CI drift detection;
- writes all 11 columns on every row. The previous CSV omitted the trailing empty `implemented`
  field on 527 rows; most of the one-time diff when this section was written is that fix.

What the first fresh scrape found (relative to the committed CSV):

- 4 genuinely new ASA options: `ActiveMapMod`, `DisableBurrowDecayTimers`,
  `UseAstraeosTraversalBuff`, `WorldBossKingKaijuSpawnTime`.
- `IgnorePVPMountedWeaponryRestrictions` moved from `Game.ini` to `[ServerSettings]`.
- `-ActiveEvent=` corrected to `inASA=Yes` (matching ASA patch 66.0), and
  `PreventBreedingForClassNames` corrected from `Unknown` to `Yes`.
- The wiki table itself is incomplete: `TamedDinoClassSpeedMultipliers`,
  `TamedDinoClassStaminaMultipliers` and the `GameDifficulties`/NPC level-override fields are
  documented in the Game.ini section but missing from the option table. The scraper only reads
  the table, so these need a secondary extraction pass or manual entries.

Rule: never hand-append to the CSV. Run the scraper (or add a manual row to a separate
`ArkServerOptions.extra.csv` if the wiki lacks it). When `--check` reports drift, review it and
update this document if the new option changes a tab/gap list.

`tools/audit-options.py` also reads the legacy C# manager
(`C:\Users\jens\MyProjects\ServerManagers`) as a third source. It is ASE-era and may contradict
the wiki; the audit reports legacy-only keys and location conflicts. Use `--no-legacy` when the
checkout is not available.

### Caveat about the `inASA` column

It is useful but not authoritative. The fresh scrape fixed one known error
(`-ActiveEvent=` was `No`, now `Yes`), and there are still wiki typos and missing rows.
Other examples:

- Several legacy `Game.ini` keys are marked `Unknown` although they are the documented ASA
  replacements (`bPvEAllowTribeWar` etc.).
- `TribeSlotReuseCooldown` is `Unknown` on the wiki but has been in the game since patch 280.114
  (and the app already models it).

Rule for implementation: `No` â†’ do not add; `Unknown` â†’ add but annotate `@Unsure` and hide
under an "experimental / unverified" grouping; `Yes` â†’ add normally. When a key matters,
verify against the installed server binary / Community Wiki before shipping.

Why #3/#4 matter: stored JSON contains explicit values, so changing a Kotlin default only
affects newly created servers. Existing profiles keep their old values. That is the correct
behaviour, but it means "official defaults" must be a **preset action** (Â§5.2, item 2), not just defaults.

On #2: the unit is genuinely ambiguous. The wiki says "in minutes" but gives the official value
as `172800.0` (2 days), which only adds up if the value is **seconds**; community tests from ASE
also report seconds. The model used to multiply by 60, so the stored default was 900. The safe
fix is to store the raw value (`15`), perform no conversion, and label it as an ARK value until
it is verified on a live server.

On `TribeSlotReuseCooldown`: it is a `Game.ini` key (correct in `Game.kt`), the UI shows minutes
and stores seconds (correct), and the only defect is the hint text above.

Also note: `GameUserSettings` and `Game` are only written to disk on save/start, while the
launch script is generated from `Administration`. There is no duplication for ports/passwords
today (the GUS model intentionally omits `Port`, `RCONPort`, `ServerPassword`), so keep it that
way: one setting, one home.

## 7. Structured / table options (dinos, engrams, levels, items, spawns)

These are the options that are not single values. They are arrays, maps, repeated keys and
nested Unreal structs. The old manager invested most of its UI here, and they are the main
reason a CSV-driven "just add fields" approach stops working.

### 7.1 Why they are a separate track

- A table can contain 1..10,000 rows; each row is itself a struct with 2-10 fields.
- ARK syntax is unforgiving: one entry per line, no spaces, quoted class names, nested `((...))`,
  repeated keys, and per-level indexed lists.
- `Game.ini` allows some keys twice (`LevelExperienceRampOverrides` for players, then tames) and
  others repeated once per row (`OverrideNamedEngramEntries`, `DinoClassDamageMultipliers`, ...).
- inisaur supports arrays, maps and structs (`@IniArray`, `@IniStruct`) but the nested ARK forms
  are not covered by tests in this repo. A spike is mandatory before building UI.
- Today these blocks survive because `ignoredKeys` preserves them and the Config Editor can edit
  them as text. Table editors are an upgrade, not a blocker. Never regress that escape hatch.

### 7.3 Architecture

**Models (`core/src/main/kotlin/ini/tables/`)**

- One data class per row shape, e.g. `DinoSpawnWeight`, `ClassMultiplier`, `NpcReplacement`,
  `EngramOverride`, `EngramAutoUnlock`, `CraftingCost`, `CraftingResource`, `StackOverride`,
  `TeleportLocation`, `SupplyCrateOverride`, `SupplyCrateItemSet`, `SupplyCrateItemEntry`.
- One aggregate per feature, e.g. `DinoTables`, `EngramTables`, `ItemTables`, `LevelTables`,
  referenced from `ShooterGameMode`.
- All collections default to empty and are omitted when empty, so a profile that never opens the
  Tables tab writes exactly the same INI as today.
- Add `@Serializable` so the DB JSON (de)serializes them like the rest of the model. New fields
  with defaults are backward compatible; no DB migration is needed.

**Serialization**

- Spike first (Wave 0). Test each shape against inisaur:
  1. [x] repeated struct line (`DinoClassDamageMultipliers=(...)` Ã— N) â€” inisaur commits
     `78cae67` (repeated struct arrays + ARK no-space formatting) and `208dffc` (single repeated
     line as a one-item struct list); the app requires a release containing both before CI can
     consume it from Maven.
  2. nested struct (`ConfigOverrideItemMaxQuantity=(...,Quantity=(...))`)
  3. nested list of structs (`BaseCraftingResourceRequirements=((...),(...))`)
  4. indexed subkeys (`LevelExperienceRampOverrides=(ExperiencePointsForLevel[0]=1,...)`)
  5. duplicate key (`LevelExperienceRampOverrides` twice)
  6. repeated scalar (`OverridePlayerLevelEngramPoints` Ã— N)
  7. indexed map (`ItemStatClamps[0..7]`, `MutagenLevelBoost[0..11]`)
  8. semicolon string list (`ValgueroMemorialEntries`)
- If inisaur handles a shape: model it with `@IniArray`/`@IniStruct`.
- If not: write a small, well-tested codec (`ArkStructCodec`) that parses/formats exactly one
  shape, and store the raw line in the model (`List<String>` or a typed model + codec). Do not
  store these as unstructured JSON blobs; the UI needs typed rows.
- Determinism: preserve user row order; always quote class names; `True`/`False` capitalized;
  floats formatted with a decimal (`.0`); no spaces after commas inside one-line structs.
- Duplicate keys: if inisaur cannot express them, split the file section into prefix/model/
  suffix raw lines (or a dedicated `IniFile` section) so the two ramps are written in order.

**Merge and import**

- Keep `ignoredKeys` as the safety net. When a key becomes modelled, remove it from
  `ignoredKeys` on import and adopt its parsed rows.
- On first open of the Tables tab, if the installed INI contains a table that has no model rows
  yet, offer "Import from installed config" (reuse `Server.getGameFromInstall`).
- Never silently drop rows that fail to parse: show them in a "raw lines" editor with a warning.

**Catalogs**

- Ship JSON catalogs under `core/src/main/resources/catalogs/asa/`: `creatures.json`,
  `engrams.json`, `items.json`, `resources.json`. Each entry has `name`, `className`,
  `category`, `nameTag`, `mod`, `asa` (`yes`/`unknown`) and aliases.
- Build them with `python tools/scrape-ark-catalogs.py`. It merges the old manager's
  `GameData/*.gamedata` files (schema and class names) with the current ASA wiki
  `Creature IDs` and `Engram class names` pages, and the `Item IDs/*` subpages.
  Generated files are committed, so runtime and CI need no network access. The scraper marks
  wiki-ASA entries `yes`; legacy-only/ASE item entries `unknown`, which the UI shows as
  "Not ASA-verified".
- Cover the catalog data with `CatalogTest` (known creatures/engrams/resources, search matching).
  The old `PrimitivePlus`/`PGM` data is deliberately excluded.
- Allow a user-provided catalog folder and a reload action later, so modded servers can extend
  the lists. Free text is always allowed; an unknown class is a warning, not an error.

**Shared editor (`ui/src/main/kotlin/components/`)**

- `DataTable<T>`: aligned header/rows, alternating row background, scrollable body and typed
  `DataTableColumn<T>` cells. Implemented, using the existing Jewel form controls as cells.
- `ClassNameCell` / `ClassPickerDialog`: free-text class name plus a searchable catalog dialog.
  Implemented; catalogs are search aids, custom class names are always accepted.
- Still pending: add/duplicate/delete/reorder beyond the current add/remove, multi-select,
  keyboard navigation, per-table filters, import/export, preview and row validation colouring.
- `MasterDetailEditor<TParent,TChild>` for crafting costs, spawn containers and supply crates.
- Toolbar: "Add row", "Import", "Export", "Reset", "Preview", row count, validation summary.

**Validation and dependencies**

- Duplicate keys (class name / tag / index) are errors.
- Values: spawn weights >= 0; percentages 0..1; levels start at 0 and are sequential; XP strictly
  increasing; engram cost/level >= 0; stack size >= 1; min <= max for quantities/qualities;
  teleport coordinates are finite.
- Cross-field warnings:
  - `ItemStatClamps` requires `ClampItemStats=true` (deep-link to Â§6.7).
  - `ConfigOverrideItemMaxQuantity` interacts with `ItemStackSizeMultiplier`
    (`bIgnoreMultiplier` bypasses it).
  - `OverridePlayerLevelEngramPoints` must have one entry per player level in the ramp.
  - `LevelExperienceRampOverrides` must list every level; warn on gaps or non-sequential indices.
  - `ConfigOverrideItemCraftingCosts` warns when the item/resource is not in the catalog (mod
    resources are normal, so this is a warning).
  - `ConfigOverrideSupplyCrateItems` warns when a crate has no item sets or an entry has no items.
- "Official defaults" per table where the game has them (level ramps, stat multipliers, mutagen).

### 8.8 Definition of done

Scalar option:

1. model + validation + UI + label/hint + CSV `implemented=Yes`;
2. serializer/validation test if non-trivial (launch args, lists, nullable, URLs);
3. included in the kitchen-sink fixture;
4. L5 smoke if it affects startup/INI behaviour, or an explicit "not verified in-game" note.

Table option:

1. golden INI test for its shape (input + expected output);
2. round-trip + idempotence with the kitchen-sink and custom fixtures;
3. CSV import/export test;
4. UI test (add/remove/duplicate/validation);
5. L5 server parse check;
6. catalog entry (or explicit free-text fallback).

### 8.9 Known limits

- We can prove ARK *parses* a value and that the file matches the documented syntax; we cannot
  prove the gameplay effect matches the wiki without in-game tests. Keep "implemented" and
  "verified in game" as separate concepts (optionally add a `verified` column later).
- The wiki is not authoritative (Â§2.1). Scraper drift is a signal, not a truth.
- No fuzzing of the whole INI parser initially; a small property-based test for scalar
  parse/format (integers, floats, booleans, quoted strings) is enough.
- UI screenshot tests are out of scope until the theme stabilises.

## 11. Risks and open questions

1. **CSV/wiki accuracy.** `inASA` is a wiki-maintained column; it is not authoritative. The
   scraper fixed `-ActiveEvent` and `PreventBreedingForClassNames`, but it cannot validate game
   behaviour. Verify risky options on a real server; keep "implemented" and "verified in game"
   as separate concepts (optionally add a `verified` column later).
2. **Wiki table gaps.** The option table omits keys that are documented only in the Game.ini
   prose (`TamedDinoClassSpeedMultipliers`, `TamedDinoClassStaminaMultipliers`,
   `GameDifficulties`/NPC level overrides). The scraper only reads the table. Plan a secondary
   extraction pass (parse the section code examples) or maintain an `ArkServerOptions.extra.csv`.
3. **inisaur coverage.** Nested ARK structs (`ConfigAddNPCSpawnEntriesContainer`,
   `ConfigOverrideSupplyCrateItems`, `Quantity=(...)`) and duplicate keys
   (`LevelExperienceRampOverrides` Ã—2) may not round-trip. The Wave 0 spike is a hard gate: if a
   shape fails, use a dedicated `ArkStructCodec` or raw-line storage, never a lossy model.
4. **Space-separated vs comma lists.** `-mods` is confirmed comma-separated. `-passivemods`
   likewise. Verify before implementing the list serializer.
5. **URLs.** Dynamic config and live tuning require **HTTP** (not HTTPS) for
   `CustomDynamicConfigUrl` on some versions; quote values in INI/CLI. Validate accordingly and
   explain in the hint.
6. **Mods in ASA are contradictory.** The wiki documents `-mods=` and its `ActiveMods` row still
   references the ASE-only `?GameModIds`; hosting guides set both. We write `ActiveMods` and always
   mirror it to `-mods=`, importing legacy `-mods` only when the INI list is empty. Both lists are
   generated from the same source. `ActiveMapMod` needs verification for modded maps.
7. **Whitelist storage.** `-exclusivejoin` needs a player list mechanism outside the INI
   (verify current ASA path/format). Do not ship a whitelist UI until the file format is confirmed.
8. **Default drift.** Changes to Kotlin defaults affect only new profiles; existing profiles need
   a preset/repair action. Decide whether "official defaults" should overwrite existing values
   (with confirmation).
9. **Tab overpopulation.** If 14-16 tabs is too much, the fallback is a left navigation tree
   (old manager style) rather than nested tab strips.
10. **JSON size.** Each server row stores all settings, `encodeDefaults=true`. Adding ~170 fields
    and table rows grows every row; check H2 row size and startup time after Phase 1/3. If needed,
    switch to `encodeDefaults=false` (still compatible, omits defaults).
11. **Catalog data.** ASA creature/item/engram catalogs must be regenerated; the old
    `.gamedata` files are ASE-era. Wiki content is CC BY-SA (attribution required). Modded
    servers need user catalogs, and catalogs must never block free-text entry.
12. **Table identity and merges.** Class names are the key. Renames/mod updates can orphan rows;
    the editor must match by key, warn on duplicates, and never silently drop rows that fail to
    parse. Preserve user order (do not sort) so diffs stay stable.
13. **Real-server test availability.** L5 needs a disposable Windows VM/runner and a SteamCMD
    install. Without it, the release checklist must mark affected options "not verified", not
    "done".
14. **Scraper fragility.** The wiki template format or Cloudflare may change. The scraper must
    fail loudly, be testable from a saved `--input` file, and never half-write the CSV (write to a
    temp file, then replace).
15. **Ragnarok/`Engine.GameSession`/`[ModInstaller]` sections** are unverified for ASA; keep them
    out of the default write path (add only when explicitly set, via `@OmitIfNull`).
16. **Native build.** `:overseer:cargoBuild` now uses `portable-pty` and builds without
    the old `conpty.lib` link error. The full Gradle build, including
    `:core:writeOverseerChecksum`, is used in CI again.
17. **inisaur single-item arrays and struct arrays.** Published inisaur `0.6.0` contains the
    single-item comma-array fix, repeated-struct arrays, single repeated-struct lines and
    `@IniString` quoting inside structs. The app depends on `0.6.0`; the temporary
    `withActiveModsFromRaw` shim has been removed. CI uses the published artifact; local builds
    can still use the sibling checkout unless `-PusePublishedInisaur` is passed.
18. **Legacy manager conflicts.** `Port`/`MultiHome` (legacy `[SessionSettings]`, wiki CLI) and
    `MaxNumberOfPlayersInTribe` (legacy `[ServerSettings]`, wiki/ASA `Game.ini`) are reported by
    the audit. The app follows the wiki. Re-check if a real ASA server rejects a value.
